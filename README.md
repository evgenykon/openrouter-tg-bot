# OpenRouter TG Bot — LLM bot в tg-чате

Telegram-бот, который добавляется в группу и отвечает только по тегу
`@<bot> <запрос>`. Контекст — история чата (ограниченная токен-бюджетом
модели). Работает только для пользователей из конфига. Сгенерированные
ответы — через OpenRouter.

## Как это работает

- **Тег, а не автоответ**: бот отвечает только когда его упомянули
  (`@bot что скажешь?`). Обычные сообщения сохраняются в историю, но
  игнорируются.
- **Доступ**: запросы и команды от юзеров не из `allowedUserIds` бот не
  выполняет: в личке и на упоминание в группе приходит «Service not available
  for you». В группах такие сообщения всё равно сохраняются в историю (бот
  видит переписку, privacy отключён), в личке — не пишутся.
- **Ответ**: стриминг из OpenRouter; пустой ответ модели повторяется до 3 раз,
  ведущее «Имя:» из ответа вырезается. Готовый ответ уходит в Markdown, а если
  Telegram его не принимает — как обычный текст; длинные ответы режутся на
  части по 4096 символов (по абзацам/строкам). Пока модель думает, бот
  продлевает статус «печатает…».
- **Контекст**: профили участников + блок актуального контекста прошлых
  дней + сырые сообщения текущего дня. Прошлые дни обязаны быть сжаты —
  компрессор отрабатывает до сборки запроса, несжатые дни в LLM не попадают.
  Всё в рамках токен-бюджета (окно модели − `maxTokens` − системный промпт − резерв 30%).
  Каждое сообщение помечается именем автора, поэтому бот понимает, кто
  спрашивает и на чью реплику отвечает (в т.ч. через reply): цитируемое
  сообщение добавляется в промпт как «(в ответ на сообщение от …)».
  Отредактированные сообщения группы обновляются в истории.
- **Посуточная компрессия**: завершённые дни (кроме текущего) сжимаются в
  сводку дня, которая затем вливается в блок актуального контекста по темам,
  позициям сторон, тезисам и выводам (у каждой темы — даты, когда она
  обсуждалась). Сырые сообщения сжатого дня удаляются. Компрессор запускается
  синхронно при сообщении группы от разрешённого юзера и при обращении в личке: пока идёт
  сжатие, бот показывает «печатает…», а после каждого дня пишет в чат отчёт
  «было/стало». Между днями пауза 2 с, чтобы не упираться в rate limit; 429 и
  сетевые ошибки ретраятся до 3 раз с растущей паузой. Если модель ответила
  ошибкой или пусто, день не фиксируется: бот сообщает об ошибке и повторит
  попытку при следующем сообщении. Когда блок контекста превышает
  `contextMaxChars`, он консолидируется — но применяется, только если модель
  реально его сократила. Формат — только обычный текст (без markdown, списков,
  таблиц, кода).
- **Личка**: бот отвечает на все сообщения, контекст — только сообщения
  этого пользователя.
- **Профиль**: у каждого разрешённого юзера есть текстовый профиль (Redis),
  которым он управляет сам. Профиль подкладывается в контекст и в групповом
  чате, и в личке — модель использует его для анализа. Профили подставляются
  безусловно (не обрезаются токен-бюджетом); при тесноте урезается только
  история чата, а профиль сжимается лишь по символам (`contextMessageMaxChars`).
  Профиль другого юзера можно посмотреть и перезаписать через `/ext_profile`.

## Настройка

1. **BotFather**: создай бота, затем обязательно
   `/setprivacy` → **Disable** (иначе бот не увидит обычные сообщения группы).
2. Добавь бота в группу.
3. Конфиги из шаблонов:
   ```sh
   cp .env.example .env
   cp config.example.json config.json
   ```
   - `.env`: `BOT_TOKEN`, `OPENROUTER_API_KEY`, опционально `REDIS_URL`
     (по умолчанию `redis://localhost:6379`) и `CONFIG_PATH` (путь к конфигу,
     по умолчанию `config.json`)
   - `config.json`:
     - `model` — модель OpenRouter для ответов; `allowedUserIds` — telegram id
       допустимых юзеров
     - `systemPrompt` / `privateSystemPrompt` — системные промпты для группы и
       лички
     - `maxContextMessages` — максимум сообщений истории в контексте;
       `fallbackContextTokens` — окно модели, если OpenRouter недоступен;
       `safetyMarginPercent` — резерв токен-бюджета, %
     - `maxTokens` — лимит ответа; `reasoningMaxTokens` — лимит reasoning для
       reasoning-моделей (иначе reasoning выедает `maxTokens` и ответ пустой)
     - `contextMessageMaxChars` — обрезка одного сообщения/профиля;
       `contextMaxChars` — порог, после которого блок контекста консолидируется
     - `compressEnabled` — включить посуточную компрессию; `compressModel` —
       необязательное переопределение модели для сжатия (по умолчанию `model`;
       reasoning-модели вроде `deepseek-r1` нестабильно отдают пустой `content` —
       для сжатия надёжнее не-reasoning модель, например `deepseek/deepseek-chat`)
4. Запуск:
   ```sh
   docker compose up -d --build
   ```
   Redis поднимается автоматически с AOF-персистентностью
   (данные — в `./data/redis`, история — в Redis, переживает перезапуски).

Настройки модели можно задавать env-переменными — они приоритетнее `config.json`,
а пустая переменная означает «взять из конфига». Удобно, чтобы менять модель
без правки файла на сервере (см. деплой ниже) или для разовых запусков:

| Env | Поле `config.json` |
| --- | --- |
| `MODEL` | `model` |
| `COMPRESS_MODEL` | `compressModel` |
| `MAX_TOKENS` | `maxTokens` |
| `REASONING_MAX_TOKENS` | `reasoningMaxTokens` |
| `MAX_CONTEXT_MESSAGES` | `maxContextMessages` |
| `FALLBACK_CONTEXT_TOKENS` | `fallbackContextTokens` |
| `SAFETY_MARGIN_PERCENT` | `safetyMarginPercent` |
| `CONTEXT_MESSAGE_MAX_CHARS` | `contextMessageMaxChars` |
| `CONTEXT_MAX_CHARS` | `contextMaxChars` |
| `COMPRESS_ENABLED` | `compressEnabled` |

## Команды

| Команда | Действие |
| --- | --- |
| `@bot <текст>` | запрос к модели (промпт — текст после тега) |
| `/start` | приветствие и начало диалога |
| `/profile` | показать профиль; `/profile set <текст>` — сохранить; `/profile add <текст>` — дополнить; `/profile clear` — очистить |
| `/ext_profile <id>` | показать профиль другого юзера; `/ext_profile set <id> <текст>` — установить |
| `/compress_chat` | список групповых чатов, где ты есть, с последним сжатым днём, размером блока и числом дней к сжатию; `/compress_chat <id>` — принудительно сжать накопившиеся дни |
| `/reset` | очистить историю чата (в личке — историю лички) |
| `/show_prompt` | показать текущий системный промпт |
| `/help` | список команд |

Можно писать `/compress_chat` и `/compress-chat`. Минус в id отрицательного
чата необязателен — некоторые клиенты его отрезают, бот найдёт чат по модулю.
Если сжимать нечего, бот объяснит, что текущий день (UTC) сжимается только
после смены суток.

Команды видны в подсказке, когда начинаешь писать `@bot` в группе, и в меню.

## Деплой через GitHub Actions

Push в ветку `main` автоматически запускает `.github/workflows/deploy.yml`:
исходники заливаются на сервер **по SSH через `rsync`**, затем выполняется
`docker compose up -d --build`. Git на сервере не обязателен. Репозиторий
может быть приватным — серверу не нужен доступ к GitHub.

Файлы `config.json`, `.env` и `data/` в git не хранятся — они остаются только
на сервере. При rsync они исключены из передачи и защищены от удаления
(`--delete` + `--exclude`, без `--delete-excluded`), поэтому при деплое
не перезаписываются и не удаляются.

Работает с GitHub Environments. Job объявляет `environment: prod`, поэтому
переменные берутся из Environments → `prod` → **Variables**, а ключ —
из Environments → `prod` → **Secrets**.

**Environments → `prod` → Variables:**

| Variable | Значение |
| --- | --- |
| `DEPLOY_HOST` | IP/хост сервера (`23.227.194.192`) |
| `DEPLOY_USER` | SSH-пользователь (`deployer`) |
| `DEPLOY_TARGET` | путь к проекту на сервере (по умолчанию `/app/openrouter-tg-bot`) |
| `DEPLOY_PORT` | опционально, порт SSH (по умолчанию `22`) |

**Environments → `prod` → Secrets:**

| Secret | Значение |
| --- | --- |
| `DEPLOY_SSH_KEY` | приватный SSH-ключ `deployer`; публичный — на сервере в `~deployer/.ssh/authorized_keys` |

В тех же **Variables** можно задать настройки модели из таблицы в разделе
«Настройка» (`MODEL`, `COMPRESS_MODEL`, `MAX_TOKENS`, `REASONING_MAX_TOKENS` и
т.д.). Деплой пробрасывает их в контейнер, поэтому для применения достаточно
передеплоить; незаданная переменная — значение из `config.json`.

Например, чтобы перевести бота на DeepSeek V4.1 Flash:

| Variable | Значение |
| --- | --- |
| `MODEL` | `deepseek/deepseek-v4.1-flash` |
| `COMPRESS_MODEL` | `deepseek/deepseek-chat` (если сжатие на новой модели отдаёт пустые ответы) |

Пользователь `deployer` должен иметь права на запись в `DEPLOY_TARGET` и доступ
к docker-сокету (`sudo usermod -aG docker deployer`). После первого успешного
деплоя рекомендуется включить строгую проверку host key
(убрать `StrictHostKeyChecking=no`).

## Импорт старой истории

`scripts/import-history.ts` заливает историю из HTML-экспорта Telegram Desktop
(«Экспорт истории чата» → HTML) в Redis — бот увидит переписку, которая была
до его запуска:

```sh
REDIS_URL=redis://localhost:6379 npx tsx scripts/import-history.ts \
  messages.html <chatId> [offsetMinutes=180] [--dry] [--full] [--skip-service] [--clear]
```

- `offsetMinutes` — сдвиг часового пояса экспорта относительно UTC (по умолчанию `180`)
- `--dry` — ничего не писать, показать разбор по дням (`--full` — без обрезки текста)
- `--skip-service` — выкинуть команды и служебные ответы бота
- `--clear` — сначала удалить все ключи чата

Скрипт пересчитывает даты в UTC, строит дневные индексы и ставит маркер
`{chat}:indexed`, так что после импорта можно сразу звать `/compress_chat <chatId>`.

## Хранение (Redis)

Space — `chat:{id}` для группы и `dm:{userId}` для лички. День считается по UTC.

- `{space}:messages` + `{space}:msg:{mid}` — сырые сообщения (прунятся после сжатия дня)
- `{space}:daymsgs:{YYYY-MM-DD}` — индекс сообщений дня
- `{space}:raw_days` — какие сырые дни есть
- `{space}:days` — какие дни уже сжаты
- `{space}:day:{YYYY-MM-DD}` — сводка дня
- `{space}:context` — блок актуального контекста
- `{space}:compress_lock` — лок компрессора (TTL 300 с, продлевается после каждого дня)
- `{space}:indexed` — маркер одноразовой миграции/индексации
- `chat:{id}:names` / `chat:{id}:users` + `user:{uid}:chats` — участники и членство
- `profile:{userId}` — текстовый профиль пользователя

При старте новой схемы старые сообщения один раз переиндексируются по дням
(`reindexDays`), а прежняя сводка `chat:{id}:summary` переносится в блок контекста
и удаляется. Фиксация сжатого дня (сводка + блок контекста + индекс + прунинг
сырья) выполняется одним `MULTI`, поэтому прерывание не оставляет чат в
полусжатом состоянии.

Контекст по токен-бюджету: окно модели берётся из
`GET /api/v1/models` OpenRouter (при недоступности — `fallbackContextTokens`),
оценка токенов — эвристика (кириллица ~2 символа/токен, остальное ~4),
плюс резерв `safetyMarginPercent`.
